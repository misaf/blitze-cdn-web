# Backup & recovery

Use this procedure to create a recoverable copy of controller state. A complete
backup preserves desired state, deployment history, inventory, configuration,
and managed certificate material.

<Callout type="error">
  Backup archives contain API credentials and private keys. Encrypt them, limit
  access, and never include them in a release artifact or source archive.
</Callout>

## Before you begin

- Record the configured paths; defaults below may have been overridden.
- Wait for deployment and certificate operations to finish so independent files
  describe one point in time.
- Define the recovery point and recovery time your service requires.
- Prepare an isolated restore host with no route to production edges.

## What to back up

| Path (default)                   | Contents                                         | Notes                                                                      |
| -------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------- |
| `.state/control-plane.db`        | Desired state, deployment snapshots, audit trail | The canonical record. Back up before any deploy.                           |
| `.state/desired-state.yml`       | The generated Ansible variable file              | Mode 0600; derived from the database and regenerated for a run.            |
| `.state/certificates`            | Managed certificate key material                 | Do not lose; forces certificate recovery.                                  |
| `.state/letsencrypt`             | Certbot account and renewal state                | Do not lose; forces account and certificate recovery.                      |
| `.env` or secret-manager records | API keys and environment-only settings           | Encrypt separately; never commit.                                          |
| `blitzecdn.toml`                 | Non-secret controller configuration              | Preserve ownership and review path overrides.                              |
| `~/.ssh/known_hosts`             | Verified edge host identities                    | Re-verify restored fingerprints through a trusted channel.                 |
| `ansible/inventory/group_vars/`  | Role variables for the edge group                | Operator-authored, not derived. The fleet itself is in the database above. |
| Service/unit configuration       | Runtime user, environment source, restart policy | Recreate with least privilege; do not embed secrets.                       |

## Backup routine

<Steps>

### Back up SQLite consistently

Use SQLite's online backup command instead of copying a live database file:

```bash
sqlite3 .state/control-plane.db ".backup '/secure/backup/control-plane.db'"
```

### Copy independent operational state

Back up certificate directories, inventory, group variables, and controller
configuration independently of the database. Snapshot certificate and Certbot
directories together; renewal can update several files in one operation.

### Encrypt and restrict the archive

Encrypt backups at rest and restrict access. The certificate directories and
environment configuration contain secrets.

### Test restoration

Restore on a separate controller without production edge access. An untested
backup is only a hypothesis.

</Steps>

## Verify the backup

Restore the files to an isolated controller, then run the recovery checks below.
Confirm that the restored site list, latest deployment ID, and certificate
metadata match the source controller. Do not point the test controller at
production edges.

## Recover offline

Stop the control-plane service before restoring. Restore the database,
certificate directories, inventory, configuration, verified `known_hosts`, and
service definition to their configured paths. Preserve restrictive ownership
and permissions, but keep production routes blocked while verifying:

```bash
blitzecdn doctor
blitzecdn validate
```

Run SQLite integrity checks if the database was recovered from disk problems:

```bash
sqlite3 .state/control-plane.db "PRAGMA integrity_check;"
```

A controller restart marks unfinished deployments `abandoned`; rerun plan before
retrying so your snapshot of the world is truthful.

## Reconnect and verify

After offline integrity and configuration checks pass, restore production
network access, verify SSH fingerprints again, and run `blitzecdn plan`. Review
the complete result before any deploy. Confirm sites, latest successful
deployment ID, audit tail, certificate SANs/expiry, and external traffic match
the recovery record.

## What loss does and does not cost

Losing controller-side certificates does **not** revoke the copies already on
the edges; they remain valid until expiry. It does force you to recover the
ACME account or re-issue/re-upload certificates. Losing the database removes
the canonical desired state and deployment history; edge configuration is not
a supported substitute for restoring it.
