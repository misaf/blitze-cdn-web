### `DeployRequest`

| Field        | Type             | Required | Default |
| ------------ | ---------------- | -------- | ------- |
| `check`      | `boolean`        | `false`  | `false` |
| `host_limit` | `string \| null` | `false`  | —       |

`host_limit` narrows the run to some edges — a canary. Names or globs, comma
separated, matching `^[A-Za-z0-9_.*-]+(?:,[A-Za-z0-9_.*-]+)*$` and at most 512
characters. Anything else is a `422`. The value is resolved against the
inventory, so it can only narrow the fleet.

### `Edge`

One edge server: how the controller reaches it, and what the world reaches. The
Ansible inventory is derived from these, so a field here is a field the
`blitzecdn` inventory plugin publishes.

| Field              | Type             | Required | Default  |
| ------------------ | ---------------- | -------- | -------- |
| `host`             | `string`         | `true`   | —        |
| `name`             | `string`         | `true`   | —        |
| `port`             | `integer`        | `false`  | `22`     |
| `private_key_file` | `string \| null` | `false`  | —        |
| `public_addresses` | `string[]`       | `false`  | `[]`     |
| `ssh_sources`      | `string[]`       | `false`  | `[]`     |
| `user`             | `string`         | `false`  | `deploy` |

`host` becomes `ansible_host`, `user` becomes `ansible_user`, `port` becomes
both `ansible_port` and `blitzecdn_firewall_ssh_port` — published from one field
so the firewall cannot close the port Ansible connects on.

`public_addresses` is what the world reaches, and is empty for the ordinary
single-homed case, where it falls back to `host`. Certificate preflight checks a
customer's hostname against these, so on a NAT'd edge they must be set.

`ssh_sources` are management CIDRs. Every edge is published the union of every
edge's sources, as a host variable — narrowing them per host would let an edge
registered before a second office existed refuse the operator sitting in it.

### `EdgeRemoval`

What `DELETE /v1/edges/{name}` did. The teardown and the deregistration fail
independently, so the outcome of the first is reported rather than implied.

| Field            | Type        | Required | Default |
| ---------------- | ----------- | -------- | ------- |
| `decommissioned` | `boolean`   | `true`   | —       |
| `hosts`          | [`HostRun[]`](#hostrun) | `false`  | `[]`    |
| `name`           | `string`    | `true`   | —       |

`hosts` carries the same per-host shape `PurgeResult.hosts` does: the counters,
the tasks that changed, and the tasks that failed. It is empty when no edge
reported at all — which is what a forced removal of a host that no longer exists
looks like.

### `RenewalResult`

The outcome of one renewal sweep, per site.

| Field     | Type       | Required | Default |
| --------- | ---------- | -------- | ------- |
| `failed`  | `string[]` | `false`  | `[]`    |
| `renewed` | `string[]` | `false`  | `[]`    |
| `skipped` | `string[]` | `false`  | `[]`    |

Three buckets rather than two, because "not renewed" has two very different
causes and only one needs a person. `failed` is a site the CA or preflight
refused. `skipped` is a site this run did not get to — the budget ran out, a
deployment held the lock, or the certificate was uploaded rather than issued and
cannot be reissued here. A skipped site is picked up by the next run, so a sweep
full of them is slower renewal rather than missed renewal.

### `ReconciliationResult`

First certificates issued for sites that were ready, and the deploy that
installed them.

| Field        | Type                          | Required | Default |
| ------------ | ----------------------------- | -------- | ------- |
| `deployment` | [`Deployment`](#deployment) \| `null` | `false` | — |
| `failed`     | `object`                      | `false`  | `{}`    |
| `issued`     | `string[]`                    | `false`  | `[]`    |
| `skipped`    | `object`                      | `false`  | `{}`    |

`skipped` and `failed` map a site name to the reason. `deployment` is `null`
when nothing was issued.

### `OriginReport`

What the fleet says about the origins it proxies to.

| Field        | Type                | Required | Default |
| ------------ | ------------------- | -------- | ------- |
| `checked_at` | `string` (date-time) | `true`   | —       |
| `edges`      | [`EdgeOriginChecks[]`](#edgeoriginchecks) | `false` | `[]` |
| `host_limit` | `string \| null`    | `false`  | —       |

Read per site rather than per edge when deciding whether something is wrong: an
origin every edge can reach is healthy, one no edge can reach is down, and one
some edges can reach is a routing or allow-list problem that a single vantage
point could never have told apart.

### `EdgeOriginChecks`

One edge's answer about every origin it was asked to reach.

| Field        | Type                | Required | Default |
| ------------ | ------------------- | -------- | ------- |
| `checked_at` | `string \| null` (date-time) | `false` | — |
| `checks`     | [`OriginCheck[]`](#origincheck) | `false` | `[]` |
| `error`      | `string \| null`    | `false`  | —       |
| `host`       | `string`            | `true`   | —       |

`error` is set when this edge said nothing usable — unreachable, the role
failed, or it published no report. A silent edge is not a passing edge.

### `OriginCheck`

One edge's answer about one site's origin.

| Field          | Type              | Required | Default |
| -------------- | ----------------- | -------- | ------- |
| `detail`       | `string \| null`  | `false`  | —       |
| `origin`       | `string`          | `true`   | —       |
| `reachable`    | `boolean`         | `false`  | `false` |
| `scheme`       | [`HttpScheme`](#httpscheme)      | `true`   | —       |
| `site`         | `string`          | `true`   | —       |
| `sni`          | `string \| null`  | `false`  | —       |
| `status`       | `integer \| null` | `false`  | —       |
| `tls_verified` | `boolean \| null` | `false`  | —       |

Two separate answers because the fixes differ. `reachable` false means DNS,
routing, a firewall, or the wrong port — the edge got nothing back at all.
`tls_verified` false with `reachable` true means the origin answered but
presented a certificate that is not valid for the SNI this edge sends, which is
the site's `origin_sni` or the origin's own certificate and nothing to do with
the network. `tls_verified` is `null` for an HTTP origin, where the question
does not arise.

`status` is whatever the origin answered a `HEAD /` with, and is not judged: a
404 or a 403 still proves the origin is up and talking, which is the whole of
what this check claims to know.

### `SiteFirewall`

Per-hostname request filtering applied at the edge. The posture is open: an
empty object serves everyone, and each list subtracts from that.

| Field               | Type       | Required | Default |
| ------------------- | ---------- | -------- | ------- |
| `allow_sources`     | `string[]` | `false`  | `[]`    |
| `allowed_countries` | `string[]` | `false`  | `[]`    |
| `denied_countries`  | `string[]` | `false`  | `[]`    |
| `denied_methods`    | `string[]` | `false`  | `[]`    |
| `denied_paths`      | `string[]` | `false`  | `[]`    |
| `deny_sources`      | `string[]` | `false`  | `[]`    |

`PATCH` replaces the whole object, so send every list you want to keep. Send
`{"firewall": {}}` to remove all rules. The `blitzecdn record firewall` CLI
command merges instead, keeping the lists you do not name.

Sources are IP addresses or CIDR networks with their host bits clear;
`203.0.113.5/24` returns `422`. Countries are ISO 3166-1 alpha-2 and require
GeoIP on the edge. See [the firewall
reference](/docs/reference/records) for how the rules compose and why
`/.well-known/acme-challenge/` is never filtered.

### `AnsibleRun`

One Ansible invocation. Required fields are `id`, `playbook`, `status`,
`started_at`, and `finished_at`. Optional fields are `return_code`, `log_path`,
and `error`; `hosts` defaults to `[]` and contains [`HostRun`](#hostrun) objects.

### `HostRun`

One edge's structured run result. `host` is required. The `ok`, `changed`,
`failed`, `unreachable`, `skipped`, `rescued`, and `ignored` counters default to
zero. `changes` and `failures` contain [`TaskResult`](#taskresult) objects; `report` carries an
operation-specific structured fact such as cache statistics.

### `RunStatus`

### `PurgeRequest`

`entries` is an array of at most 500 [`PurgeEntry`](#purgeentry) objects. `purge_all` defaults
to `false`; `host_limit` is an optional comma-separated edge pattern. Supply
entries or `purge_all`, never both or neither.

### `PurgeResult`

Contains `purged_at`, the requested `entries`, `purge_all`, `host_limit`, and
per-edge `hosts`. Read-only `complete` is true only when every edge in scope
purged; read-only `failed_hosts` names edges that may still serve the object.

### `StatsRequest`

`host_limit` is the only field and is optional.

### `CacheStatsReport`

Contains required `collected_at`, optional `host_limit`, and an `edges` array of
[`EdgeStats`](#edgestats) objects.

### `EdgeStats`

`host` is required. `collected_at`, `nginx_reachable`, connection counters,
per-site `sites`, and `error` describe one edge. A missing timestamp and an
error indicate that edge did not return a report.

### `SiteCacheStats`

Contains required `site` and an `outcomes` mapping of Nginx cache-status labels
to request counts.

### `PreflightReport`

Contains required `site` and a `checks` array of [`PreflightCheck`](#preflightcheck) objects.

### `PreflightCheck`

Contains required `name`, `passed`, `severity`, and human-readable `detail`.

### `PreflightSeverity`

`blocking`, `advisory`. A blocking failure prevents an ACME request; an
advisory is reported but does not make issuance impossible.

### `Workflow`

Crash-visible progress for work that crosses transaction systems. Required
fields are `id`, `kind`, `status`, `operator`, `created_at`, and `updated_at`.
`resource_id` and `error` are optional; `steps` defaults to `[]`.

### `WorkflowKind`

`deployment`, `rollback`, `certificate`

### `WorkflowStatus`

`pending`, `running`, `succeeded`, `failed`, `needs_review`

### `WorkflowStep`

Contains required `name` and `completed_at`, plus an operation-specific
`details` object.
