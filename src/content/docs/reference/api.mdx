# HTTP API

Verified against the OpenAPI schema of `BlitzeCDN control plane` v1.1.0.

Every route below except `GET /health` requires the `X-API-Key` header.
Ten failed authentications from one client address within a minute return
`429`. Deployment and rollback routes return `202 Accepted` with a queued
record; poll `GET /v1/deployments/{id}` for the outcome.

## Request and retry rules

- Send `X-API-Key` on every `/v1/*` request. A missing or invalid key returns
  `401`; repeated failures can return `429` for the source address.
- Read-only `GET` requests are safe to retry with bounded backoff.
- Do not blindly retry `POST` mutations. A timeout can occur after the server
  committed a record mutation or queued a deployment. Query records, deployments,
  and audit events before deciding what to do next.
- `202` means queued, not converged. Poll the returned deployment ID until it is
  terminal and inspect retained output on any non-success status.
- The API has no client-supplied idempotency key in v1.1.0.

Common error bodies use FastAPI validation details for `422`. Authentication,
conflict, and missing-resource responses contain a short `detail` string:

```json
{"detail":"invalid API key"}
```

Never log the request header when capturing an error response.
