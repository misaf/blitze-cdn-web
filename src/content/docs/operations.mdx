# Operations

## Deployment checklist

1. Verify backups of `.state/control-plane.db`.
2. Verify inventory addresses and SSH host fingerprints out of band.
3. Confirm the non-root deployment user has narrowly managed sudo access.
4. Set management CIDRs; an empty list deliberately fails.
5. Run `blitzecdn doctor`, `validate`, and `plan`.
6. Review check-mode output and apply with `deploy --yes`.
7. Inspect `status DEPLOYMENT_ID` and edge health externally.

## Troubleshooting

- Authentication 503: configure `BLITZE_API_KEYS`; malformed/short keys fail at
  startup.
- Inventory missing: create `ansible/inventory/hosts.yml` or set
  `BLITZE_INVENTORY` to an absolute path.
- SSH host-key failure: validate the new fingerprint; never bypass checking.
- Firewall assertion: provide at least one trusted CIDR containing the current
  management source before retrying.
- Nginx validation failure: inspect bounded stderr/status, correct desired state,
  plan, and deploy. Nginx is not reloaded after a failed validation.
- Deployment conflict: inspect current controller process and lock owner. Do not
  delete a live lock file; filesystem locks release when their process exits.
- Timeout: confirm network/package-repository health and host state. A timeout is
  not proof that no remote changes occurred; rerun plan before retrying. On
  timeout the controller signals the whole `ansible-playbook` process group
  (`SIGTERM`, then `SIGKILL` after five seconds), so its per-host workers stop
  rather than converging edges after the run is recorded as timed out.
- Deployment stuck `queued`/`running`: API deployments run on a worker thread, so
  the record only settles when Ansible finishes. If the controller was restarted
  mid-run, startup marks the record `abandoned`; rerun plan before retrying.
- Authentication 429: ten failed authentications from one client address within a
  minute are throttled. Behind a reverse proxy this counts all clients together.
- Group variables ignored: `group_vars` must sit beside the inventory file, in
  `ansible/inventory/group_vars/`. Elsewhere Ansible silently skips it and roles
  fall back to their defaults.
- Disk exhaustion: stop new work, preserve the database, free space outside
  `.state`, run SQLite integrity checks, then validate before deployment.
- ACME request failure: confirm every requested hostname resolves to the edge
  addresses, port 80 is public, the HTTP-only site was deployed first, Certbot
  is installed on the controller, and all edges are reachable over SSH.
- Certificate upload failure: provide an unencrypted PEM private key and a PEM
  chain whose leaf SANs cover every configured site hostname.

## Certificate renewal

Call the certificate request endpoint periodically for ACME-managed sites, then
deploy when certificate metadata changes. Certbot reuses its controller-side
account and renewal state beneath `.state/letsencrypt`. Back up both that
directory and `.state/certificates`; losing the state does not revoke deployed
certificates but forces account and certificate recovery.

## Release

Run every quality gate, build wheel/sdist, inspect their contents, update the
version and changelog, tag the reviewed commit, and publish from an isolated CI
identity. Releases must never contain `.env`, `.state`, inventories, SSH keys,
Vault passwords, or certificate keys.
