# Release

Use this checklist to release the control plane and edge collection without
shipping runtime state or breaking their versioned contract.

This page is for maintainers. Operators changing an installed release should
use [Upgrading](/docs/guides/upgrading); local development setup belongs in
[Contributing](/docs/contributing).

## Before you begin

- Use a reviewed target commit and an isolated CI publishing identity.
- Confirm the control-plane and edge versions that will be released together.
- Ensure `.env`, `.state`, inventory, SSH, Vault, and certificate key material
  are absent from the release workspace.

<Callout type="error">
  A release containing runtime state or key material is a credential incident,
  not only a packaging defect. Stop and rotate affected credentials.
</Callout>

## Process

1. Run every quality gate against the target commit — lint, tests, and type
   checks.
2. Build the wheel and sdist, then inspect their contents for anything that
   should not ship.
3. Update the version and changelog.
4. Tag the reviewed commit.
5. Publish from an isolated CI identity — no operator machine holds the
   publishing token in interactive a shell.

## Keeping the versioned contract in sync

A release is more than one repository. Releasing the control plane and the edge
collection changes what the docs describe, so the two must move together:

- If desired-state shape changed in a way older roles cannot honour, bump
  `DESIRED_STATE_VERSION` before release.
- Update the affected reference pages and version labels in the documentation.
- Review commands, API shapes, configuration defaults, and role variables
  against the artifacts being released.

## What "CI identity" means

Tagging and publishing should both come from short-lived credentials issued to a
CI run over your reviewed commit, not from a developer's long-lived token. This
limits what a leaked environment or a local session could do to a single release
run.

## Verify the release

- Install the published artifacts in an empty environment.
- Run `blitzecdn doctor` against example configuration without production
  credentials or inventory.
- Confirm the edge collection version matches the control-plane pin.
- Build the documentation and run its browser, accessibility, and link checks.
- Inspect the published archive contents again, not only the local build output.
