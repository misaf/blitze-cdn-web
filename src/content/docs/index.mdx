servers. Start from what you need to accomplish, not from the repository's

## Operate BlitzeCDN

The [operator runbook](/docs/operate) is the canonical command path. It keeps the
complete standalone lifecycle on one page and explicitly separates:

- fresh installation;
- state-preserving repair;
- state-preserving upgrade;
- deployment and rollback;
- backup and isolated restore;
- destructive fresh rebuild;
- unsupported state-preserving uninstall;
- supported complete purge.

Use a focused procedure when the runbook links you there:

| Outcome                                              | Procedure                                                |
| ---------------------------------------------------- | -------------------------------------------------------- |
| Choose an install, upgrade, rebuild, or removal mode | [Lifecycle](/docs/operate/lifecycle)                     |
| Learn on a first deployment                          | [First deployment](/docs/operate/first-deployment)       |
| Move a real hostname to HTTPS                        | [Take a site live](/docs/operate/go-live)                |
| Plan, canary, deploy, or roll back                   | [Deploy and roll back](/docs/operate/deploy)             |
| Add, change, or retire edge servers                  | [Manage edge servers](/docs/operate/edges)               |
| Publish DNS                                          | [Publish DNS](/docs/operate/dns)                         |
| Issue, upload, renew, or inspect TLS                 | [Manage certificates](/docs/operate/certificates)        |
| Protect or recover controller state                  | [Back up and restore](/docs/operate/backup-restore)      |
| Collect evidence and repair a failure                | [Troubleshoot and repair](/docs/operate/troubleshooting) |
| Handle uncertain serving state                       | [Incident response](/docs/operate/incident-response)     |
